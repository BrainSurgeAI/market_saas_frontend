## 🚀 体验功能

### 作为 Market（市场）用户，您可以：

#### 1️⃣ **对 SKU-002（智利三文鱼）- SHIPPED 状态**
- ✅ 点击"确认收货" → 状态变为 RECEIVED
- ✅ 点击"拒收" → 状态变为 REJECTED（需填写原因）

#### 2️⃣ **对 SKU-003（新西兰羊排）- RECEIVED 状态**
- ✅ 点击"完成处理" → 状态变为 COMPLETED

#### 3️⃣ **对其他商品**
- ⚪ SKU-001（PENDING）：暂无操作（等待供应商发货）
- ⚪ SKU-004（COMPLETED）：已完成，无需操作
- ⚪ SKU-005（REJECTED）：已拒收，等待供应商重新发货

## 🎯 功能演示

### ✅ 1. 加载动画
- 首次进入页面会看到 **0.8秒** 的加载动画
- 模拟真实网络请求延迟

### ✅ 2. 操作确认对话框
- 点击任何操作按钮会弹出确认对话框
- 拒收操作需要填写原因
- 可以取消操作

### ✅ 3. 状态实时更新
- 操作后有 **1秒** 的处理延迟（模拟 API 调用）
- 成功后立即更新表格显示
- 发货/收货时间自动更新

### ✅ 4. Toast 提示
- 操作成功：绿色提示 "商品状态已更新为 XXX"
- 操作失败：红色提示 "更新换货商品状态时出错"

### ✅ 5. 统计面板
- 实时显示各状态商品数量
- 自动计算并更新统计信息

### ✅ 6. 控制台日志
打开浏览器控制台可以看到模拟操作的日志：
```
[Mock] 商品 2 状态已更新为 RECEIVED { reason: undefined }
```

## 🎨 UI 演示内容

### 📊 统计卡片显示
```
总商品数: 5
待发货: 1    (灰色)
已发货: 1    (蓝色)
已完成: 1    (绿色)
```

### 🎭 状态徽章颜色
- **PENDING** → 灰色徽章 "待发货"
- **SHIPPED** → 默认徽章 "已发货"
- **RECEIVED** → 默认徽章 "已收货"
- **REJECTED** → 红色徽章 "已拒收"
- **COMPLETED** → 默认徽章 "已完成"

### 🔘 操作按钮
- **单个操作** → 直接显示按钮（如："确认收货"）
- **多个操作** → 显示下拉菜单（"确认收货"/"拒收"）
- **无操作** → 显示灰色徽章 "暂无操作"

## 🧪 测试场景

### 场景 1: 确认收货
1. 找到 **智利三文鱼整切**（状态：已发货）
2. 点击"确认收货"按钮
3. 在对话框中点击"确认"
4. 观察：
   - ✅ 1秒后状态变为"已收货"
   - ✅ 收货时间自动填充
   - ✅ Toast 提示成功
   - ✅ 统计数字更新

### 场景 2: 拒收商品
1. 找到 **智利三文鱼整切**（如已收货，刷新页面重置）
2. 点击操作按钮展开菜单
3. 选择"拒收"
4. 在对话框中填写原因（如："质量不合格"）
5. 点击"确认"
6. 观察：
   - ✅ 状态变为"已拒收"
   - ✅ 徽章变为红色
   - ✅ 按钮变为"暂无操作"

### 场景 3: 完成处理
1. 找到 **新西兰羊排**（状态：已收货）
2. 点击"完成处理"按钮
3. 在对话框中点击"确认"
4. 观察：
   - ✅ 状态变为"已完成"
   - ✅ 统计中"已完成"数量+1

## 🎯 演示要点

### ✨ 展示给团队时重点说明：

1. **角色感知** - Market 用户看到的操作与 Provider/Customer 不同
2. **状态流转** - 严格的状态转换规则，不允许非法操作
3. **用户体验** - 加载状态、错误处理、空状态都很完善
4. **实时反馈** - 操作后立即更新，无需刷新页面
5. **数据完整** - 显示发货/收货时间，支持查看历史记录
