# 菜单缓存系统使用说明

## 概述

菜单缓存系统实现了用户菜单数据的本地缓存，避免每次页面刷新都重新从服务器获取菜单数据，提高应用性能和用户体验。

## 功能特性

### 1. 自动缓存管理
- **登录后自动缓存**: 用户成功登录后，系统会自动获取并缓存菜单数据
- **过期时间管理**: 默认缓存24小时，过期后自动从服务器重新获取
- **角色关联**: 缓存与用户角色关联，不同角色的菜单分别缓存

### 2. 智能缓存策略
- **优先使用缓存**: 页面加载时首先检查本地缓存
- **缓存未命中时获取服务器数据**: 如果没有有效缓存，则从服务器获取
- **自动更新**: 从服务器获取新数据后自动更新缓存

### 3. 登出时清理
- **自动清理**: 用户登出时自动清理所有菜单缓存
- **安全考虑**: 确保用户切换时不会混淆菜单数据

## 缓存数据结构

### localStorage 存储格式

```javascript
// 缓存键格式
"user-menu-cache-{primaryRole}"

// 缓存数据结构
{
  "primaryRole": "pricer",
  "userRoles": ["pricer"],
  "menuConfig": {
    "teams": [...],
    "navMain": [...],
    "projects": [...]
  },
  "timestamp": 1672531200000,
  "expiresAt": 1672617600000
}
```

### 相关存储项

- `user-roles`: 当前用户的角色数组
- `current-organization`: 当前选中的组织信息
- `user-menu-cache-{role}`: 各角色的菜单缓存数据

## API 修改

### 登录成功处理

登录表单已更新，在登录成功后会：
1. 解析JWT获取用户角色信息
2. 将角色信息存储到 `localStorage`
3. 在后台异步获取并缓存菜单数据

### 登出处理

登出时会清理：
- 所有菜单缓存 (`clearAllMenuCache()`)
- 用户角色信息 (`localStorage.removeItem('user-roles')`)
- 当前组织信息 (`localStorage.removeItem('current-organization')`)

## 性能优化

### 1. 减少网络请求
- 首次访问页面时，如果缓存有效，直接使用本地数据
- 避免每次页面刷新都调用 `/api/user/menu`

### 2. 提升加载速度
- 菜单数据立即可用，无需等待网络请求
- 减少页面加载时间

### 3. 缓存管理
- 自动过期机制，确保数据及时更新
- 合理的缓存大小，避免占用过多存储空间

## 故障排除

### 常见问题

1. **缓存未生效**
   - 检查 `user-roles` 是否正确存储
   - 确认缓存格式是否正确
   - 查看控制台是否有相关错误信息

2. **菜单数据过期**
   - 缓存默认24小时过期
   - 可以手动清理缓存: `clearMenuCache()`

3. **角色切换后菜单不更新**
   - 系统会根据新角色重新获取菜单
   - 如有问题，可以手动刷新: `refreshMenu()`

### 调试步骤

1. 打开浏览器开发者工具控制台
2. 运行 `menuCacheDebug()` 查看缓存状态
3. 检查网络请求，确认是否调用了菜单API
4. 查看localStorage中的存储数据

## 配置选项

### 缓存过期时间

在 `menuCache.ts` 中可以修改默认过期时间：

```typescript
const DEFAULT_EXPIRES_IN = 24 * 60 * 60 * 1000; // 24小时
```

### 禁用缓存

如需禁用缓存功能，可以修改 `setMenuCache` 调用：

```typescript
setMenuCache(role, menuData, { enabled: false });
```

## 注意事项

1. **安全性**: 缓存数据存储在 localStorage 中，不包含敏感信息
2. **兼容性**: 支持 localStorage 的现代浏览器
3. **存储空间**: 菜单数据通常较小，不会造成存储压力
4. **开发调试**: 仅在开发环境中提供调试工具，生产环境不会暴露
